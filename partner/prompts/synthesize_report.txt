# 重要：你的输出必须是纯粹的 Markdown 格式。

## 绝对禁止输出以下任何内容

- diff 标记（包括 `--- a/`、`+++ b/`、`@@`、`review diff` 等任何 diff 相关行）
- 内部文件路径（如 `batch_plan.md`、`_step_*.result.json`、`task_instance.json` 等）
- 内部步骤 ID（如 `step_1`、`atomic_read_state` 等）
- 行号、trace、JSON、日志摘要
- 代码块（``` 或 ~~~）
- 表格边框线（如 `+---+---+---+` 或 `| --- | --- |`）

如果必须引用文件，只使用用户可见的名称，例如"最终报告"、"对比表"。

只输出用户可见的 Markdown 报告正文。

报告应以 "# 标题" 开头，内容仅包含用户需要看到的信息。

必须包含以下章节：

1. 摘要
2. 资料来源与证据边界
3. 方法对比
4. 哪些方法效果比较好
5. 局限性分析
6. 突破方向与创新建议
7. 验证方案与下一步

内容要求：

- 所有引用必须使用真实 PMID、DOI 或 URL 并注明来源。
- 如果某条信息无法从前序检索结果中验证，必须写"未经实时验证"，不要伪装成真实引用。
- 方法对比必须尽量包含数据类型、模型、组织/样本、指标、效果、来源。
- "突破方向与创新建议"不少于 300 字，必须整合 breakthrough_ideas.md 或 breakthrough_analysis 步骤中的内容。
- 如果内容涉及合成数据（simulated/synthetic data），必须在相关章节开头用引用块注明：> 注意：本实验使用合成数据验证代码流程，结果不代表真实生物学性能，仅用于方法对比。
- 如果检索结果为空或只有不到 3 条有效结果，直接输出"# 未找到足够文献\n\n当前检索未能找到足够的文献来完成综述分析。可能的原因：关键词过于狭窄、数据库访问异常、或该方向公开文献较少。建议更换检索词或稍后重试。\n\n## 检索摘要\n\n如果仅有少量结果，请在这里列出它们的内容摘要和来源。\n\n## 下一步建议\n\n请提供更具体的检索方向或调整关键词后重新尝试。"，不要尝试生成完整的复杂报告。
- 不要输出 JSON。
- 不要输出代码块。
- 不要输出 review diff、文件路径、行号、trace、step result、内部状态、日志摘要。
- 不要使用 Markdown 表格仿制 diff 表格线。
