# ADR 0004：以手动稳定核心作为生产基线

**状态**：accepted  
**日期**：2026-08-25

## 背景

01/02 最初的手动消息路径能直接确认用户指令、逐步汇报并交付结果。后来 Campaign、持续迭代、
Research Loop、RL 和 deterministic fast path 同时加入，形成多个执行所有者和多套消息格式。
实跑出现只发结果文件、步骤消失、模板化报告、写了下一步却没有可靠执行、自进化替代业务推进等退化。

## 决定

生产默认改为 fail-closed 的 `manual_stable`：用户消息是唯一任务触发器；普通任务只规划一次；逐步骤
消息是兼容合同；任务结束后等待用户。全部自治能力显式关闭。保留历史代码和证据供后续独立实验，
但它们不能被普通 planner 选择，也不能在进程启动或 cron 中复活。

五个实例保留各自角色，同时最多运行两个，通过显式手动切换轮换。实例启动对共享配置只读，避免
最后启动的实例把全局 workspace 路径改成自己的目录。

## 后果

- 当前不会自动连跑整夜或自动 RL promotion，这是有意的产品边界，不是未报告故障。
- 用户能稳定地看到收到、步骤和结果，开发者也有单一可复现路径。
- 后续重新研究自治能力时必须是 opt-in 实验，证明不会回退本基线后才能讨论晋升。
