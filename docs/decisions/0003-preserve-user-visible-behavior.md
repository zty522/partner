# ADR-0003：把已验证的用户体验作为运行合同

- 状态：accepted
- 日期：2026-08-24

## 背景

Campaign 的 deterministic fast path 提高了可靠性和成本可控性，却逐渐把用户体验压缩成“任务结束后发送一个通用 PDF 和一句摘要”。结果是代码、测试和文件可能真实执行，用户仍看不到操作步骤；不同项目的报告也被同一正文模板抹平。此前 01 已验证有效的浏览器截图、视觉说明和过程消息，没有被提升为跨架构合同，因此新路径可以无声绕过它们。

## 决策

1. 所有非报告 Campaign WorkItem 必须真实送达 `started`、`executed`、`finished` 三阶段进度回执；缺任一阶段不得验收完成。
2. 浏览器任务继续执行更强的逐关键步骤截图、视觉模型描述、图片和文字送达合同；三阶段消息不能替代视觉回执。
3. 机器 JSON、用户报告、即时消息和 EvidenceManifest 是四类不同产物，不能互相替代。
4. 报告正文由实例领域 renderer 决定；PDF 公共层只提供排版，不再提供跨项目固定正文模板。
5. 已实机验证的良好能力只有同时写入 canonical 文档、结构化运行证据、回归测试和变更记录后，才算进入产品基线。

## 后果

单个 WorkItem 会多发送少量关键消息，因此 Scout 使用 compact 模式控制噪声。验收会更严格，但以后更换模型、调度器或快速路径时，不能再以“后台成功”为由牺牲用户可理解性。
