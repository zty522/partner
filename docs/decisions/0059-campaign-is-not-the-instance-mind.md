# ADR 0059：Campaign 不是实例的“心智循环”

**日期**：2026-09-02  
**状态**：Accepted；旧常驻 Campaign 已停，实例原生循环待实现  
**生产基线**：`manual_stable` 不变

## 问题

Campaign 是外部批处理与实验治理容器：预先创建 WorkItem、控制双槽/预算/截止时间，并由 watchdog 恢复。
旧 Sprint18 服务还每小时创建一个 `Campaign 定时进度摘要`，交给允许实例列表中的第一个实例 02 发送。
因此用户在 09:03、00:19 等时间看到 02 周期汇报，即使没有项目新动作。这是控制面噪声，不是认知或学习。

它与期望的工作方式相反：真实的人不会每隔固定时间机械“学习一次”，而是在做事、观察结果、发现冲突或
知识缺口时切换到学习，形成或修正理解，然后回到原任务。

## 决策

1. Campaign 只保留为有边界的批量 benchmark、baseline/candidate 对照和离线审计容器，不再作为实例日常心智。
2. 已停止并禁用 `partner-sprint18@campaign_74833fad4af8.service`；历史账本不删除。
3. Campaign 支持 `report_interval_seconds=0`，表示控制面静默。Sprint18 runner 默认使用 0；周期 watchdog
   可以恢复进程，但不得创建任务或向用户发“我还活着”的消息。
4. 日常长期运行迁移为实例原生、事件驱动循环：

```text
真实输入/上轮终态
→ 读取项目 Receipt、未完成动作与相关记忆
→ 执行一个可验证项目动作
→ 检查结果是否出现失败、矛盾、不确定性、知识缺口或重复低效
   ├─ 否：直接执行项目下一动作
   └─ 是：插入一次受限 observe/select/diagnose/learn/candidate/verify
           → 巩固有效经验或拒绝 Candidate
           → 返回被中断的项目下一动作
```

5. 每个实例拥有自己的项目状态、记忆、学习触发器和恢复点；全局资源层只分配最多两个运行槽，不替实例选题、
   不规定学习周期、不生成内容报告。
6. 用户消息只对应有意义状态变化：收到任务、开始真实动作、关键发现/失败、产物与证据、下一动作/需要用户边界。
   WAITING、watchdog、租约续期和无变化监控只写本地账本。

## 学习触发条件

学习是项目执行中的元认知中断，而不是按时间触发。允许触发的事实包括：truth/claim 失败；相同机制再次失败；
结果与预测显著冲突；决策不确定性高且下一证据价值足够；Receipt 的下一动作缺少知识；用户明确负反馈；或新证据
推翻已有策略。单纯日期变化、运行时长、空闲、定时器到点和“需要更多 RL 样本”均不能触发业务动作。

## 迁移边界

当前只完成第一阶段：停止旧服务、关闭周期消息并确立架构。实例原生自治循环尚未接入生产，所以不能声称
02/04/05 已按此模式长期自治。实现时必须复用现有 Event、Receipt、Episode、Candidate、Reward 与真值门，
而不是再造另一条旁路；通过真实单实例验收后，再在资源仲裁器下开放最多双槽。
