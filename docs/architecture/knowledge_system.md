# 分级文档与动态上下文系统

## 目标

保留完整知识，但每一步只加载当前决策需要的内容。文档是长期记忆，不是每次全量注入的 prompt。

## 分级

- L0：`docs/catalog.yaml` 路由元数据，每次可读。
- L1：自我定位、真实性规则、当前基线，小而稳定。
- L2：领域、架构、项目和 playbook，按实例/任务选择。
- L3：当前项目状态、最新 Receipt、任务证据，在运行时生成。
- L4：原始日志和历史归档，只在追溯时读取相关片段。

## 选择流程

1. 规则层强制选择 L1，并按实例和标签筛选 L2。
2. 语义选择只在候选集中排序，不得越过 authority/default_load 约束。
3. 加载最新项目状态和 Receipt 作为 L3。
4. 按字符预算截断，记录选了什么、为什么、用了多少预算。

ADR 0048 增加了一个未接生产的 shadow 候选：在 canonical docs 之外，先保护最小 Receipt handoff，再按
当前 query 检索同项目的 state/action/reward trajectory，最后附有 SHA256 的研究摘录。它用于验证动态
经验是否能补足项目承接，不改变默认 selector。字符预算必须按最终序列化 bundle 计算，来源注释和代码围栏
也占预算；只统计正文会产生“账面合规、实际超限”的假象。

ADR 0049 将该 bundle 交给独立下游消费者后又增加一条硬约束：任何被列入 `selected refs` 的完整证据对象
必须真实出现在最终上下文中，不能先登记再被末尾截断。预算分配应保护完整 Receipt、优先放置任务相关研究
证据，并对同类 Top-K 做来源去重；跨语言机制别名必须是可审计的路由规则，不能靠评价 oracle 暗示答案。

## 不变量

- L4 不默认加载。
- 过时文档不能覆盖 canonical/current 事实。
- 每个片段带来源，不生成无法追溯的拼接上下文。
- 选择结果不直接修改原文档。
- 缺少必读文档时显式失败，不静默降级为猜测。
- 轨迹检索必须限定同一 project identity；跨项目经验只能经显式迁移实验使用。
- “selected Receipt”不足以通过交接门，Receipt ID 与 next action 必须真实存在于最终上下文。
- “检索命中”不等于“下游可用”；至少用与评价器分离的消费者验证结构化事实恢复。
